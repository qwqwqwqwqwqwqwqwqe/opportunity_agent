# 字段契约修复与官网链接诊断面板

前端入口：http://localhost:8000/v2。刷新后发起查询，Run 信息下方的“官网链接与处理阶段”会独立展示搜索候选、正文读取、LLM 提取、格式错误、验证拒绝、已验证字段；显示原始字段值和稳定原因码。搜索发现的链接明确标为未验证，不能称为已确认正确项目。

进度经原 Redis/AgentEvent 通道持久保存，GET Run 的 source_progress 聚合这些事件；即使 A2A 结果丢失，之前已保存的事件仍能查看。历史 Run 可以重新打开查看，但旧版未记录的事件不能补造。命中 SQL 缓存时展示已有证据链接，明确“本轮未重新读取”。所有标题和值经过 HTML 转义，拒绝非 HTTPS 和携带凭据链接。

提取修复：按字段使用不同 Pydantic 子类型，GRE value 的 JSON Schema 是严格枚举。模型将原文完整日期复制到 value 时，程序进行通用规范化；不会为缺少年份补年。格式不合格时只额外修复一次，共享原提取截止时间。项目标题中的短名与官方全称可以在有来源且首字母一致时绑定，不新增跨学校别名。GRE 通用政策可不声明申请季，但来源中的硬性申请季冲突仍拒绝。

真实页面单例：CMU MSAII 申请页，5.25 秒得到并验证 deadline=2026-12-09、gre_policy=required，无格式修复和拒绝。完整测试 Run 293986e3f8b341ef9f7deed3426cd172 的 Completion=PASS，保留13条官网进度事件；第一页身份校验拒绝，第二页通过。这是单例，不是跨学校准确率保证。
