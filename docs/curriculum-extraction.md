# 课程结构化提取（2026-10-17）

旧实现将 ProjectData JSON Schema 放入模型上下文，但 Extraction.fields[].value 为 object，格式正确不等于课程粒度正确；也未要求将学分下限、二选一规则与课程分离。

新实现：Extraction.curriculum 使用强类型 Curriculum JSON Schema，courses 每项一门课，course_rules 记录分组、原始要求、关联课程代码、choose 和分组学分。未知单课学分留空，不将总选修学分分摊。前端提供单独规则表单，原有项目 JSON 存储无需迁移；索引自动包含新字段，仍需用户确认后生效。

真实回归显示逐项课程输出较长：培养/课程组输出上限8000 tokens，申请组4000；默认单次时间60秒（配置仍限制5–60秒），整项目300秒、正常2次加最多1次格式修正不变。显式设置30秒的部署仍遵循该配置，不自动放大无限预算。

实际输出模式仍由 PROJECT_IMPORT_OUTPUT_MODE 控制，默认 prompt：模型看到 Schema，服务端做 Pydantic 严格校验；这不等于已启用网关原生 strict JSON Schema。json_schema 模式已有配置入口，但必须由网关支持，不能把 prompt 模式宣称为原生约束生成。即使原生Schema约束生成，课程粒度和事实真实性仍需业务校验与人工确认。

提取边界拒绝明显多课程代码、分号/换行列表、选课要求冒充课程、分组最低学分冒充单课学分和组内重复。正常标题中的 and/&/与 不拆开。泛型 fields 中的课程同样校验，不能绕过类型约束。错误反馈只含路径与类型，项目全程最多一次结构修复且扣模型调用预算；失败保留可编辑草稿，不自动发布。

局限：这些校验不是通用课程实体识别器；没有代码和明确分隔符的隐性课程集合仍可能漏过。历史已存课程不强制拒绝，避免旧项目无法编辑；重新提取仅覆盖模型候选，不覆盖无提取来源的用户填写字段。courses_complete 仍为 false，未知学分、来源无法精确定位均不视为核验成功。

测试涵盖中英文单课、自然连词、课程代码、OR、多课分号/换行、分组学分、重复、未知单课学分、非法类型/额外字段、单次纠正、预算扣减和重复失败停止。真实模型回归另看实际任务结果，桩测试不代表任意学校准确率。
