# V3 画像助手

聊天入口已收敛为四项能力：更新个人画像/偏好、查询已记录的数据、普通聊天、解释已有官网变化通知。保留原登录、会话、SSE、审批及冲突交互；不需要新数据库迁移。

## 使用

重建当前服务后 Ctrl+F5：

```powershell
docker compose -f compose.applyops.yml up --build -d api worker
```

Compose 默认访问 `http://localhost:8001/v3`；本地脚本默认是 8000。左侧进入「画像助手」。

- `我的托福是105分`：首次录入生成待确认提案，确认之前数据库不改变。
- `我的托福更新为110分`：已有标量不同，沿用 V2 冲突弹窗，选择保留旧值或使用新值后生效。
- `查看我的画像`、`我的托福多少分`：读取当前已保存值，不把待确认信息当作已保存。
- `我目前有哪些申请项目`、`CMU的MSAII还缺哪些材料`：查询用户已记录项目、要求和材料；准备完成不等于已提交，不宣称覆盖学校全部要求。
- `查看1月15日的待办`、`本周有什么日历事项`：按用户当地当前年/日期筛选。带日期的查询不包含未排期事项。
- `我有多少封未读通知`、`解释最新一封官网变化通知`：只读取本人站内信，不标记已读。
- 多封通知且没有明确指定时先澄清；在信箱详情点击「在画像助手中解释」会绑定具体通知，可继续问“这对我意味着什么”。连续追问绑定原通知，不因新信到达而悄悄换成新的“最新”通知。
- `你好`、一般申请准备问题：配置模型后自然回复；没有模型时提供规则查询、画像提取和明确的功能介绍，不冒充真实模型效果。

通知解释引用已保存的分析、当时个人依据和官方证据，不重新抓取官网，不调用个人影响 Agent，也不自动发信。画像改变后需到官网监控重新检查，不能把历史结论理解为最新核验。

## 边界

- 唯一可提出的写操作为 `profile.change`、`preference.change`。提取、规范化、字段白名单和标量冲突处理复用 V2；追加经历保留追加语义，相同值不重复提案。
- 修改项目、DDL、材料、任务、日历和监控配置，请到对应页面操作。聊天不会生成这些命令，也不会自动排期。
- 不启用 RAG、Research、全网检索、SQL 生成或任意工具执行。
- 数据查询使用服务端按用户身份构建的快照；通知及其分析/证据按 user_id 校验。复制他人的通知 ID 不会回退到其他信件或暴露内容。
- 模型只负责查询结果的自然语言组织及普通聊天；不能修改提案集合。提案和冲突说明保持确定性，防止模型声称已保存。
- 历史 V3 WorkflowOrchestrator 类仍为旧验收/评测保留，正式 ApplyOps 聊天单例已切换为 ProfileAssistant；V2 入口不受影响。

## 界面

采用与 V3 工作台一致的灰白背景、低饱和绿色、圆角消息卡片和输入框。增加欢迎页与查询快捷入口、画像入口和聊天历史；技术 Run 记录折叠显示，不常驻干扰阅读。通知详情可直接转到画像助手解释，手机宽度无横向溢出。
